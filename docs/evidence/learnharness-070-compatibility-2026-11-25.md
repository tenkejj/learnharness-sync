# LearnHarness 0.7.0 compatibility qualification, 2026-11-25

## Version discrepancy

The earlier packaged real-data round trips used a **separate 0.6.1 AppImage**, not the owner's installed 0.7.0 application. The pinned source file was `build/qualification/real-sync/LearnHarness-0.6.1-x86_64.AppImage` (196,784,591 bytes; SHA-256 `b8a033eb7421677893d96e4988b30153fdfe4fc6f0dc456f7947161bba041b98`). `scripts/test-packaged-managed-roundtrip.py` copied it into each newly created disposable `a-home/Applications` and `b-home/Applications` under `build/packaged-managed-roundtrip-*`. `src-tauri/managed/host.sh` copied and independently hash-checked it inside an ephemeral extraction directory; `worker.sh` executed `/app/learnharness` inside the subordinate-UID bubblewrap namespace. See `docs/evidence/packaged-real-roundtrip-2026-11-25.md`. The ephemeral extraction directory changes on every run. No prior real-data test used 0.7.0.

## 0.7.0 binary and source

The official [LearnHarness v0.7.0 release](https://github.com/amosblomqvist/learnharness/releases/tag/v0.7.0) was downloaded separately to `build/qualification/learnharness-070/LearnHarness-0.7.0-x86_64.AppImage` (196,652,282 bytes; SHA-256 `772b5e04d380cbe8a72a75dbff269aeb6a47f4d4452711b1da8059a872067613`, matching the GitHub release asset digest). The 0.7.0 tagged source commit is `0292b85bcce080cc685f85d174a8cb2cc553a0ad`; 0.6.1 is `cb25c8e49b85eed9e78315584731cad73a0118a6`. The source tarballs were extracted only under ignored `build/qualification/learnharness-070/`.

The tagged `src/store/chats.ts`, `src/core/contracts/chat.ts`, `src/core/contracts/graph.ts`, and `src/store/source-organization.ts` are byte-for-byte equal across these tags. Persisted chat version remains 2; graph format remains 1; source organization format remains 1. In 0.7.0, folders and chat placements can now be authored through the app UI/API and persisted in `graph/source-organization.json`. The strict adapter accepts only chat folder records and refuses imported-file placements or paths. The settings parser adds appearance fields `compactSessionList`, `transcriptMaxWidth`, and `adaptiveQuestions`; settings remain device-local and are not transferred. Custom-provider model discovery additionally reads `limit.context` and `limit.output`; provider credentials and configuration remain device-local. The plugin task record parser changes `maxTurns` optionality, but plugin records are outside the supported transfer inventory. PDF figure annotations and path-bearing attachments are not supported.

A disposable 0.6.1 profile clone was opened in the real 0.7.0 app. The app verified its four messages and graph; pre/post hashes of six supported records plus `settings.json` were unchanged during that read-only reopen. This verifies that specific read path, not all possible migrations. A fresh disposable 0.7.0 app run created and reopened four native messages, three propositions, two chains, provenance and four saved layout positions. A real 0.7.0 API run created one folder and a conversation placement. The native profile adapter validated all seven real records (5,248 bytes) and rejected a folder cycle and an imported path.

## Packaged qualification

`python scripts/test-managed-launcher.py <ordinary AppImage> <0.7.0 AppImage> --release 0.7.0 --host-display` exited 0. It checked the real app, subordinate-UID snapshot, Tauri WebView snapshot, malformed content and recovery, killed helper and recovery, unauthorized bridge command, active writer refusal, supervisor termination and restart. Its one initial run failed because a QA oracle hardcoded `/slot/vault`; the oracle now accepts the separately versioned `/slot/vault-070` path. A subsequent WebView smoke failure was not reproduced on direct retry; the complete suite later exited 0. Disposable Btrfs subvolume deletion was denied by the kernel (`EPERM`); retained test vaults were left read-only.

`python scripts/test-packaged-managed-roundtrip.py <private acceptance AppImage> 0.7.0` exited 0 with two independent packaged Tauri/native peers, disposable managed 0.7.0 profiles and identities. A authored four messages, three propositions, two chains and one chat folder. Authenticated QUIC delivered seven content records (5,248 bytes) to B's version-specific quarantine, then B's durable backed-up apply was verified by reopening the real app. B authored a Unicode follow-up; the reverse transfer and apply were verified by reopening the real app on A. The run also exercised active-writer refusal, injected ENOSPC after backup, helper SIGKILL after the journaled generation switch, explicit recovery and retry. The earlier 0.6.1 run on the same updated private acceptance package also exited 0 with six records (4,932 bytes), preserving regression compatibility. These are two peer processes on one host; no physical 0.7.0 two-computer acceptance is claimed.

The normal AppImage has no acceptance console. The private acceptance build is test-only and must never be uploaded as a release asset. Production supports only a narrowly qualified text and graph subset using the custom `qa-model` test provider. Other provider output formats, attachments, side chats, imported notes, plugin/job records and arbitrary existing 0.7.0 profiles remain unsupported and are refused. The owner's personal 0.7.0 profiles and credentials were not opened or modified.
